# 17. Repository Architecture

Status: locked for structure; module contents grow with the implementation tasks (doc 25).

## 17.1 Layout

```
syntheticscaling/
├── configs/                  # every launchable condition is a YAML file here
│   ├── students/             # s025m.yaml … s1b.yaml         (StudentConfig)
│   ├── teachers/             # qwen2.5-1.5b-instruct.yaml …  (TeacherConfig, pinned revision SHA)
│   ├── generation/           # main_v1.yaml, ablation_temp*.yaml (GenerationConfig)
│   ├── training/             # base_v1.yaml, phase2_v1.yaml   (TrainingConfig incl. per-size LR table)
│   ├── evaluation/           # primary_v1.yaml, secondary_v1.yaml (EvalConfig)
│   └── experiments/          # pilot/, main/, dsweep/, ablation/ — one YAML per run, generated by scripts/make_matrix.py
├── data/
│   ├── prompts/              # versioned prompt pools (jsonl + sha256 + build manifest); small enough for git-lfs or DVC
│   ├── raw/                  # base corpus shards, benchmark sources (not in git)
│   └── processed/            # tokenized memmaps, subsampled synthetic sets (not in git)
├── synscale/                 # Python package (the user-suggested top-level dirs map to these submodules)
│   ├── config/               # schemas.py (pydantic), loader.py (YAML composition + overrides)
│   ├── tracking/             # ids.py (experiment IDs), manifest.py (run manifests), index.py
│   ├── models/               # param_count.py (closed-form counts + config search), llama_like.py (nn.Module)
│   ├── generation/           # prompt_pool.py, vllm_generate.py, filters.py, subsample.py, gen_manifest.py
│   ├── training/             # data.py (memmap + packing), trainer.py, schedules.py, checkpoint.py
│   ├── evaluation/           # lm_eval_runner.py, nll_eval.py, format_probe.py, decontam.py
│   └── analysis/             # aggregate.py, regression.py, tstar.py, ste.py, plots.py
├── scripts/                  # thin CLIs: make_matrix.py, launch.py, generate.py, train.py, evaluate.py, build_index.py, analyze.py
├── tests/                    # unit tests (schemas, IDs, param counts, subsampling determinism, matrix invariants)
├── results/                  # manifests + small eval JSON only (see doc 18)
├── docs/                     # research deliverables 00–25
└── paper/                    # abstract, introduction, methods drafts; figure scripts write to paper/figures
```

Rationale for a single package rather than top-level `generation/`, `models/`, … directories: importable, testable modules with one namespace, no path hacks in scripts, and one `pyproject.toml` with optional extras (`train`, `gen`, `eval`, `analysis`) so the generation machine (vLLM) and the training machines (torch + flash-attn) can install disjoint dependency sets.

## 17.2 Configuration schemas

Defined in `synscale/config/schemas.py` (pydantic v2, strict validation). Summary:

| Schema | Key fields | Invariants enforced |
|---|---|---|
| `StudentConfig` | n_layers, d_model, n_heads, n_kv_heads, head_dim, d_ff, vocab_size, context_length, tie_embeddings, rope_theta, init | `n_heads % n_kv_heads == 0`; `n_heads*head_dim == d_model` |
| `TeacherConfig` | family, hf_repo, **revision (commit SHA)**, nominal/exact params, variant (instruct/base), weight_dtype, tensor_parallel, thinking_mode=False | precision identical across teachers (checked at matrix level) |
| `GenerationConfig` | prompt_pool + sha256, system_prompt_id, temperature, top_p, max_new_tokens, samples_per_prompt, sampling_seed, filter_ruleset, target_student_tokens | shared by all teacher conditions in a study |
| `PhaseConfig` | tokens, batch_tokens, lr_peak, lr_min_ratio, schedule (wsd/cosine), warmup_tokens, decay_tokens, weight_decay, betas, grad_clip, loss_mask, packing, replay_fraction | WSD requires decay_tokens; warmup ≤ tokens |
| `TrainingConfig` | tokenizer + sha256, context_length, precision, base_phase, synthetic_phase, checkpoint_rule=final, eval_every_tokens, seed_base, seed_phase | final-checkpoint rule only |
| `EvalConfig` | harness_version, primary_tasks, secondary_tasks, num_fewshot, batch_size, eval_seed, nll_sets | |
| `ExperimentConfig` | study, arm (synthetic/base_only/matched_real/human_instruct), student, teacher?, generation?, training, evaluation, dataset_ref, dataset_sha256, variant | synthetic arm needs teacher+generation; controls carry no teacher |

Experiment YAMLs reference fragments by path and may override leaf values (`overrides: {training.seed_phase: 2}`); `load_experiment()` composes, validates, and returns an `ExperimentConfig` from which the ID and manifest derive.

## 17.3 Data flow

```
prompt_pool (versioned) ──┐
teacher checkpoint (SHA) ─┼─► vllm_generate ─► samples.jsonl ─► filters ─► pool_T (all teachers, same rules)
decoding config ──────────┘                                                     │
                                                                                ▼
base corpus ─► tokenize (student tok) ─► base_pretrain(S, seed_base) ─► ckpt_base(S)   subsample(pool_T, D_syn) ─► set_{T,D}
                                                                          │                         │
                                                                          └──────► phase2(S, set, seed_phase) ─► ckpt_{S,T,D,seed}
                                                                                                    │
                                                                                  lm-eval + NLL ─► results/<id>/eval/*.json
                                                                                                    │
                                                                                  build_index ─► index.parquet ─► analysis (regression, T*, STE, plots)
```

## 17.4 Entry points (all config-driven)

| Script | Input | Output |
|---|---|---|
| `scripts/make_matrix.py --study main` | student/teacher/generation/training/eval fragments + seed tiers | `configs/experiments/main/*.yaml` (one per run) + invariants check |
| `scripts/generate.py configs/generation/main_v1.yaml --teacher configs/teachers/X.yaml` | prompt pool | `results/generation/<...>/samples.jsonl.zst` + manifest |
| `scripts/build_dataset.py` | filtered pool, D_syn, variant | `data/processed/<teacher>.<D>.<variant>.bin` + sha256 |
| `scripts/train.py configs/experiments/main/<id>.yaml` | base ckpt + dataset | checkpoint + manifest + train log |
| `scripts/evaluate.py --run <id>` | checkpoint | `results/<id>/eval/*.json` |
| `scripts/build_index.py` | results/ | `results/index.parquet` |
| `scripts/analyze.py --study main` | index | tables, figures, fitted models, bootstrap CIs |

## 17.5 Testing policy

- Unit: parameter-count formulas vs. hand computation; ID determinism; subsampling determinism; filter rules on fixtures; schedule shapes; packing masks.
- Matrix invariants: for every pair of `synthetic` runs with equal (student, D, variant, seed), all fields outside `teacher.*`/`dataset_*` are equal; all teachers share `weight_dtype`, decoding config, prompt-pool SHA.
- Smoke: 25M model, 2M tokens, CPU or single GPU, end-to-end generate→train→evaluate on a 200-prompt pool, run in CI on every commit.
